# DualSub 技术方案

> 版本：v0.1（规划稿，未开始编码）
> 日期：2026-10-08
> 参考项目：[dlsandy/Transub-Player](https://github.com/dlsandy/Transub-Player)（WPF/Windows，无开源 License，**只参考架构思路，不复用任何代码**）

---

## 1. 项目定位

**打开视频，字幕跟上。**

面向「手头没有字幕文件、也不想折腾字幕站」的观众：本地视频（或网络流）丢进播放器，画面立即开始播放，实时语音识别在后台生成字幕，翻译随后跟上，全程本地推理、离线可用。

**产品边界（学原项目的克制）**：

- 目标是「能看懂、跟得上」，**不是发行级字幕**——不追求时间轴完美、不追求译文润色
- 有现成字幕就用现成的，实时字幕是兜底
- 定位个人工具，不做字幕编辑器、不做云端服务

**与 Transub-Player 的差异点**：

| 维度 | Transub-Player | DualSub（我们） |
|---|---|---|
| 平台 | 仅 Windows | Windows / macOS / Linux |
| 技术栈 | WPF + C# | Tauri 2 (Rust) + Web 前端 |
| 模型策略 | 全离线，按需下载 | 同（拍板：全离线） |
| 界面语言 | 英/日/韩/中 | 仅中文（后续有需要再说） |
| 附加功能 | 流媒体录制、字幕站匹配、与 Transub 云服务联动 | 砍掉云联动，聚焦本地体验；流媒体播放保留、录制后置 |

## 2. 竞品架构拆解（学什么、避什么）

### 2.1 Transub-Player 的架构

```
WPF 主窗口
 ├─ libmpv 嵌入（视频渲染 + 播放控制）
 ├─ AsrPipeline：ffmpeg 抽音频 → whisper.cpp (GGML turbo) 流式转写
 ├─ LlamaServerProcess：拉起 llama-server 跑 Hy-MT 翻译 GGUF
 ├─ ModelStore：模型按需下载（HuggingFace）+ 校验
 └─ 杂活：更新器、安装包、首启向导、文件关联、四语言 i18n
```

从其文件树（约 130 个源文件、1.13MB C#）看工作量分布：**核心管线（ASR/MT/mpv）约占 1/3，产品化杂活（下载器/安装包/向导/设置）占 2/3**。这个比例直接决定我们的排期——技术演示一周能跑通，打磨到能日常用要两三个月。

### 2.2 值得抄的产品决策

1. **进度可见**：实时字幕生成时明确显示「正在识别 xx:xx–xx:xx」，绝不让人以为卡死
2. **降级不阻塞**：翻译模型没装好/翻译慢时，原文照常上屏——看剧永不停
3. **三模式 = 一个数字键**：`1` 译文、`2` 原文、`3` 双语，零学习成本
4. **字幕稍滞后属正常**：明确告诉用户这是实时的代价
5. **退出即干净**：拉起的子进程（llama-server、ffmpeg）全部随主进程退出
6. **便携版/安装版双发行**：设置目录跟随安装形态

### 2.3 原项目的坑（我们不踩）

- 原项目把字幕渲染交给 mpv sub 轨——**双语排版和样式控制受限**。我们改为前端 overlay 渲染，双语上下排、样式、字号、描边全部 CSS 控制
- 原项目模型默认从 HuggingFace 拉，国内下载体验差。我们内置 **hf-mirror.com 镜像源**与手动导入
- 原项目塞了一堆场景化词库（AV glossary 之类）耦合在核心里。我们把词库做成可选插件目录

## 3. 技术选型（拍板）

| 层 | 选型 | 理由 |
|---|---|---|
| 应用壳 | **Tauri 2**（Rust 核心 + 系统 WebView） | 体积小、内存占用低；Rust 生态直接对接 whisper-rs / libmpv；拍板跨平台 |
| 前端 | **Vue 3 + Vite + TypeScript** | 与团队现有技术栈一致；界面仅中文，不做 i18n 框架 |
| 视频内核 | **libmpv**（`libmpv`/`libmpv-rs` crate） | 格式覆盖之王；播放控制、硬件解码、网络流全现成 |
| 语音识别 | **whisper.cpp**（经 `whisper-rs` 进程内集成） | GGML/GGUF 模型，CPU 可跑，支持 GPU（Vulkan/Metal/CoreML）；与原项目同源 |
| 翻译 | **llama.cpp 的 `llama-server`**（sidecar 子进程，HTTP 调用） | 与原项目同思路：独立进程 + OpenAI 兼容 API，进程隔离、崩溃不连累主程序 |
| VAD | **silero-vad**（`ort` ONNX Runtime 推理） | 跳过静音段省算力，切句更准 |
| 音频抽取 | **ffmpeg**（sidecar，按需分段抽取 16k 单声道 wav） | 原项目同路线（AsrAudioExtract）；mpv 本身不好做 PCM 旁路 |
| 打包 | Tauri bundler（msi/dmg/AppImage）+ Tauri updater | 官方更新器覆盖三端 |

**两个关键架构决策（方案内定稿，开发前不再摇摆）：**

### 决策 A：视频画面如何进 Tauri 窗口

Tauri 主窗口是 WebView，视频画面进不来 DOM。两个可行方案：

- **方案 A1（MVP 采用）：原生子窗口分层**。mpv 渲染到一个位于 WebView 之下的原生子窗口（Windows: 子 HWND；macOS: NSView layer；Linux: X11 subwindow），WebView 背景透明盖在上面，字幕 overlay 是 DOM 元素。优点：实现简单、性能零损耗；缺点：窗口层级操作有平台细节，圆角/毛玻璃等花哨窗口效果受限。
- **方案 A2（后续演进）：GPU 纹理共享**。libmpv render API 软渲染到共享内存/纹理，再合成进 WebView 或 wgpu 表面。效果最干净但工作量大、三端调试深。

> MVP 走 A1，A2 挂在 v2 备忘，不做提前量。

### 决策 B：字幕渲染归属

- **不用 mpv sub 轨渲染**（原项目路线），改为 **WebView DOM overlay**：前端拿字幕事件流自己画。换来的是双语上下排、逐行样式、淡入动画、点击查词（后续学习功能）全部自由。
- mpv sub 轨仅用于**加载现成字幕文件**的场景（SRT/ASS 原生渲染，省事且保真）。

```
│  │  WebView（Vue 3，透明背景，盖在上层）             │  │
│  │   ├─ 播放控制栏 / 播放列表 / 设置               │  │
│  │   ├─ 字幕 Overlay（DOM，双语渲染）★             │  │
│  │   └─ 字幕进度指示器（识别中 xx:xx–xx:xx）        │  │
│  └───────────────────────────────────────────────┘  │
│  ┌───────────────────────────────────────────────┐  │
│  │  libmpv 原生子窗口（视频画面，垫在下层）          │  │
│  └───────────────────────────────────────────────┘  │
└───────────────┬─────────────────────────────────────┘
                │ IPC（Tauri command / event）
┌───────────────▼─────────────────────────────────────┐
│  Rust 核心（src-tauri）                              │
│  ├─ player：libmpv 封装（播放/seek/音量/进度事件）      │
│  ├─ asr：实时识别管线 ★                              │
│  │    调度器 → VAD 切句 → whisper-rs → 时间戳对齐      │
│  ├─ mt：翻译管理（llama-server 生命周期 + 请求队列）    │
│  ├─ models：模型仓库（下载/校验/断点/镜像/手动导入）     │
│  ├─ media：ffmpeg sidecar（分段抽音频）               │

  whisper.cpp(进程内)    llama-server(sidecar)
  ffmpeg(sidecar)        （GGUF 翻译模型）
```

### 4.1 实时识别管线（核心，详细设计）

这是整个项目的灵魂，按「边播边出字幕」设计：

```
播放时钟 ──► 调度器（追帧但不追播）
              │  以「识别落后播放进度 ≤ N 秒」为目标
              ▼
        ffmpeg 抽取 [t0, t1] 音频段 → 16kHz mono PCM
              │
              ▼
        silero-VAD 过滤静音 / 切句（句尾停顿 > 0.5s 断句）
              │  纯静音段直接跳过，不进 whisper
              ▼
        whisper-rs 推理（small/turbo 档位可选）
              │  输出 segment 级时间戳（相对 t0）
              ▼
        时间戳对齐：换算回媒体绝对时间
              │  处理 VAD 切句与 whisper 原生段落的边界融合
              ▼
        字幕事件（start, end, text）──► 前端 Overlay
              │                          │
              ▼                          ▼
        覆盖追踪器（哪些时间段已有字幕）   翻译队列（异步）
```

**关键设计点：**

1. **调度策略**：播放是硬实时，识别是软实时。seek 跳转时直接丢弃当前识别窗口、从新位置重启管线；倍速播放时识别允许落后，落后超阈值则丢中间段保最新（保证字幕追的是「正在看的」而不是「没看的」）。
2. **切句**：VAD 停顿切句为主，whisper 段边界为辅；单段上限 ~15s，避免长段翻译延迟。
3. **结果幂等**：同一段音频不重复识别（覆盖追踪器记录已识别区间，seek 回看命中缓存直接出字幕）。
4. **进度可见**：每次推理前后端同步「正在识别 xx:xx – yy:yy」，Overlay 显示半透明占位。
5. **档位**：模型分 `base（快）/ small（均衡）/ turbo（准）` 三档，默认 small；设置页可换，切换即热重载。

### 4.2 翻译管线

- `llama-server` 以 sidecar 常驻，OpenAI 兼容 `/v1/chat/completions`
- 翻译模型：**Hy-MT-1.2B 级别的小模型 GGUF**（原项目同款思路，中/日/韩/英互译，CPU 可跑）；模型清单与原项目对齐即可，不自训
- 请求队列按字幕句为单位，批量合并（一次 prompt 带 3–5 句上下文，译文连贯性更好且省 token）
- **翻译缓存**：`(源文本, 源语言, 目标语言)` 为键内存缓存 + 磁盘缓存；seek 回看、重播零开销
- 翻译未就绪时原文先上屏（双语模式显示「原文 + 识别中」），译文到达后平滑替换——学原项目「看剧永不停」原则
- 源语言自动猜：文件名启发式（如 `JP`、`生肉` 标记）+ 首段识别结果语言检测，设置页可手动改

### 4.3 模型仓库

- 目录：安装版 `%LOCALAPPDATA%/DualSub/models`（Win）、`~/Library/Application Support/DualSub/models`（mac）、`~/.local/share/DualSub/models`（Linux）；便携版用 exe 旁 `data/`（学原项目）
- 下载源：HuggingFace 直连 + **hf-mirror.com 镜像**（默认镜像，国内可用性优先），支持切换
- 完整性：sha256 校验 + 断点续传 + 手动导入（用户自己下好拖进来）
- 模型清单以 JSON 配置内置（whisper 三档 + 翻译模型 + VAD），可随版本更新

### 4.4 子进程治理

所有 sidecar（ffmpeg、llama-server）由 Rust 侧统一持有：

- 启动记录 PID，主进程退出时**强制收割**（Windows: Job Object；Unix: 进程组 kill）——学原项目「退出即干净，不留后台」
- llama-server 崩溃自动重启（指数退避，连续失败 N 次降级为「仅识别不翻译」并提示）

## 5. 功能范围

### MVP（M1–M4，核心闭环）

- 本地视频打开/拖放/最近播放，播放控制（进度/音量/倍速/全屏/截图）
- 实时字幕（whisper small 默认档）+ 原文/译文/双语三模式切换
- 本地翻译（llama-server + 小模型）+ 翻译缓存
- 模型下载管理（镜像源、校验、手动导入）
- 现成字幕文件优先加载（SRT/ASS，同目录自动嗅探）
- 中文字幕样式设置（字号/颜色/描边/位置）
- 快捷键：`1/2/3` 模式、`Z/X` 字幕偏移、`V` 显隐、`F` 全屏、空格暂停

### V1.0（发布门槛）

- 网络流 URL 播放（http/m3u8）
- 播放列表 + 倍速识别调度
- 播放位置记忆、字幕偏移记忆（按文件持久化）
- 首启向导（模型下载引导 + 格式关联可选）
- 自动更新（Tauri updater）
- 三平台安装包（msi / dmg / AppImage）

### V2 备忘（不进首版排期）

- GPU 纹理共享渲染（决策 A2）
- 视频片段录制、字幕导出为 SRT
- 「学习模式」：点击查词、生词本
- 词库插件目录（领域术语热替换）
- 移动端（Tauri 2 mobile，仅探索）

### 明确不做

- 字幕编辑器 / 时间轴调整工具
- 云端账号体系与同步
- 与字幕站自动匹配下载（版权敏感，且原项目留给自家云产品 Transub 做）

## 7. 风险清单

| 风险 | 等级 | 应对 |
|---|---|---|
| **WebView 透明层 + 视频子窗口的三平台层级差异**（macOS NSView 层级、Linux Wayland 不支持子窗口定位） | 高 | MVP 优先做 X11/Windows；Wayland 降级为独立视频窗口或走 A2 方案；M1 首周先做层级技术验证（spike） |
| **实时识别 CPU 占用**（低配机 small 档推理吃满核） | 高 | VAD 过滤静音可省 30–50% 算力；档位默认 small、提供 base；超阈值自动降档 |
| **whisper 对 BGM 大的片源准确率差**（动漫/动作片） | 中 | 产品文案管理预期（「能看懂」不是「发行级」）；音轨分离后置 |
| **模型下载国内可达性** | 中 | hf-mirror 默认 + 手动导入兜底 |
| **llama-server 三平台分发**（二进制体积、GPU 差异） | 中 | 用 llama.cpp 官方预编译 release，GPU 失败平台降级 CPU 版 |
| **Tauri WebView 差异**（Linux WebKitGTK 渲染兼容性） | 中 | CSS 只用保守特性，不做依赖 WebView 高级合成效果的 UI |
| **whisper-rs / libmpv crate 版本跟进** | 低 | 锁版本，升级走专项验证 |
